This change log highlights some of the more significant changes as the project evolves.

- October 21, 2026: Added Flutter project to develop mobile apps for receiving the data via BLE. The ESP32 will be the BLE server. Mobile apps will receive this BLE data for display on phones or tablets. I only created the basic framework so far (empty mobile apps). The goal is to broadcast this data via BLE so motorcycle tablets or phones can receive and display it. If this becomes prime path for the display of the data, I will get a smaller ESP32 with no display. For now the Waveshare ESP32-S3 display will perform this function. In order for a smaller non-display device to perform this function a fuel reset and time setting feature will need to be added to the mobile app(s). 

- October 22, 2026: Android app and BLE server working. Here is a video playlist showing the system: [https://www.youtube.com/playlist?list=PLWVnSqkvN5Vg](https://www.youtube.com/playlist?list=PLWVnSqkvN5Vg) Google Play Store Listing: [https://play.google.com/store/apps/details?id=com.jroal.mobile_701_display](https://play.google.com/store/apps/details?id=com.jroal.mobile_701_display) (internal testers only, not yet open to public).

- October 24, 2026: Added setting features. Created setting to keep display ON while the app is open. Added setting to select which BLE server to connect to. This handles the situation where 2 or more BLE servers are within range. By default it looks for any available. Then it lists the servers found so the user can select which one they connect to.

- October 27, 2026: Added a floating overlay option to show remaining range in the Android app (now version 4, 1.0.4). Also changed to not use full screen, leaving the navigation bar exposed. 

- November 1, 2026: Fixed the display falsely reporting ABS OFF a few seconds after the ABS prove-out roll. The ABS OFF inference (0x129 bit 3 held low) was removed because that bit is low whenever the bike is idle; the display now shows only ABS ON or off-road. The off-road request now starts within ~100 ms of power-up and is sent continuously until another module sends it, the bike moves, or the switch is turned off. Added an SD-card auto-disable, firmware/BLE protocol versions (INFO characteristic, About dialogs) and a diagnostic `_capture` build.
- October 31, 2026: Added an off-road ABS switch to the ESP32 display and the Android app. The setting is stored in ESP32 NVM. The display sends the request (CAN 0x300, 0F 00.., every 100 ms for 6 s, copied from the cruise control module in the logs) only if off-road ABS is not already active and no other module is sending it. It takes effect on the next key cycle. Moved the date/time under the fuel label on the display and removed it from the Android app. Removed the nosd build; the standard build now runs with or without an SD card. It checks for the SD card at start and if none is found after a few seconds it disables the SD card data logging.
